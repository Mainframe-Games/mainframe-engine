# 2026-11-07: G19 phase 4, NativeAOT exports

Branch `feature/g19-native-aot`. Plan: [G19 NativeAOT](../plans/2026-11-07-g19-native-aot.md). Design:
[Protected exports](../../docs/design/protected-exports.md) (moved out of `future/`, "Changes from the proposal, phase 4"),
[Game export → NativeAOT](../../docs/design/game-export.md#nativeaot), [Crash reporting → Symbols](../../docs/design/crash-reporting.md#symbols).

## What changed

- **Engine AOT-clean:** `IsAotCompatible` on `MainframeEngine` and the Steamworks shims; `MainframeEngine/.editorconfig`
  makes every trim, single-file and AOT diagnostic an error. Fixed: `Node` (type-level `[DynamicallyAccessedMembers]`;
  the override and signal-handler scans in nested classes; `ReflectedType()`), `Resource` (public properties), `Tween`
  (nodes/resources annotated, `Color`/`Quaternion` without reflection), `SdlEventBatch` (`[DynamicDependency]`),
  `ConfigFile`, `TypeRegistry`, `GameAssemblyLoader` (`[RequiresUnreferencedCode]`, editor-only), `SteamworksLoader`
  (`IsShimAvailable`), `CrashBundleWriter`.
- **Build:** `build/MainframeGame.props` turns `-p:MainframeNativeAot=true` into `PublishAot` for game projects, adds the
  target OS's shim and Facepunch assembly as ILC references with `build/steamworks/Facepunch.Steamworks.<build>.rd.xml`,
  publishes no `steamworks/`, managed PDBs or XML docs, and keeps third-party ILC warnings (IL2104, IL3053, IL3000,
  IL3002) from failing warnings-as-errors. `BundleAppHost.targets` skips NativeAOT. `NativeAppBundle` (start of
  `GameHost.Run`) points a NativeAOT process in `X.app/Contents/MacOS` at `../MonoBundle`. The package carries the rd.xml
  files in `buildTransitive/steamworks/`.
- **Export:** `nativeAot` in `DesktopExportOptions` and project format (no format bump), `ExportPlan` arguments,
  `native-aot-host` and `native-aot-ignored`, the stage's managed-assembly check, `SymbolCollector.CollectNative`, the
  Export dialog's Native AOT row, `mf-export --native-aot` (legacy form).
- **Crash frames (ADR 0260):** `CrashFrame.NativeImage`/`NativeOffset`/`NativeImageId`, `NativeImageId` (Mach-O UUID, ELF
  build id, PE CodeView, from memory or files); `mf-symbolicate` gains `NativeSymbols` and `NativeSymbolizer`
  (`llvm-symbolizer`, `atos`, `addr2line`).
- **Checks:** `NativeAotNeedsAHostOfTheTargetOs`, `NativeAotIgnoresReadyToRunAndSingleFile`, runner tests over a fake
  NativeAOT publish, the format test, `NativeFrameTests`, `NativeAotTests` (bundle base directory, rd.xml in sync),
  `NativeAotExportHasNoManagedAssemblies` (real SDK, opt-in `MAINFRAME_NATIVE_AOT_TESTS=1`); `template-smoke.sh`
  `NATIVE_AOT=1` (`just template-smoke-aot`), `build/linux/run.sh aot` (`just template-smoke-aot-linux`; the image gains
  clang and zlib1g-dev).
- **Docs:** protected-exports (moved), game-export, asset-pipeline, crash-reporting, milestones (G19 ✅), AGENTS.md,
  README, landing page; links to the old path repointed.

## Decisions

- [ADR 0259](../decisions/0259-native-aot-exports.md): phase 4 stays in G19 (owner, 2026-11-07); `MainframeNativeAot`
  instead of a global `PublishAot`; type-level annotations instead of generated override flags; macOS keeps the
  MonoBundle layout; third-party warnings stay warnings.
- [ADR 0260](../decisions/0260-native-crash-frames.md): native frames carry image, offset and build id; the platform's
  symbolizers resolve them.

## Dead ends

- `-p:PublishAot=true` on the command line: NETSDK1207 on the generator project.
- The first NativeAOT build ran headless but never quit windowed: no node had `OnProcess` (metadata trimmed), so the
  loading screen never faded and `--max-frames` never counted. A swapchain-recreation loop seen in one sample was a
  red herring.
- A standalone experiment showed NativeAOT marshals a non-blittable struct through `PtrToStructure(ptr, typeof(T))`, which
  suggested Facepunch was fine; against a running Steam client its blittable callbacks failed ("missing structure
  marshalling data"). Only the rd.xml `MarshalStructure` directive fixed it.
