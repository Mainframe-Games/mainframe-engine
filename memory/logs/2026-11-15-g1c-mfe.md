# 2026-11-15: G1c `mfe` CLI (G1.16)

Branch `feature/g1c-mfe`, stacked on `feature/g1c-checks` (#213). Plan: [G1c mfe](../plans/2026-11-15-g1c-mfe.md). As
built: [Animation and skinning → The `mfe` CLI](../../docs/design/animation.md#the-mfe-cli).

## What changed

- **`Tools/MainframeEngine.Cli/`** (`mfe`, in `MainframeEngine.slnx`): `MfeCli` (groups, help, exit codes and error
  mapping), `MfeProject` (`--project` or the nearest `project.mfproj`; sets and restores `ContentPaths.ProjectDirectory`
  and `AssetDatabase.Current`; gravity from `physics3D.gravity`), `CommandLine` (copied from `mf-l10n`),
  `AnimCommands` (`rig`, `poses`, `bake` for pose and edit scripts, `describe`, `check`, `list`; text and `--json`).
- **Engine:** `HumanoidMap.Store(modelPath)` writes the map into the `.mfmeta` `humanoid` setting.
- **`just mfe`** (`[no-cd]`: it runs in the current directory, so a project there is found).
- **Tests:** `MfeCliTests` (10, in-process on a temp project with the test character); the test project references the
  CLI.
- **Docs:** animation.md (The `mfe` CLI, Testing), the proposal (G1.16 built and its changes), AGENTS.md (Build & Run,
  Project Structure).

## Decisions

- None needing an ADR: the plan's design notes and the proposal's "Changes" entry for G1.16.

## Dead ends

- `AssetJsonContext` is internal to the engine, so the CLI could not write the map into the `.mfmeta` itself; it moved
  into the engine as `HumanoidMap.Store`, next to `PoseLibrary.Link`'s sidecar writing.

## Verified

- `just build`, Release `-warnaserror`, `just test`, `just format-check`, `just shaders-check`, `just state-guard`,
  `check.sh` (numbers in the PR).
- By hand: `just mfe anim poses` in the repo; `just mfe anim bake squat.json` and `describe` in a scratch project with the
  test character (0 errors, 0 warnings; the crouch reads back as its script).
- `just test-render` not run: nothing here draws.
