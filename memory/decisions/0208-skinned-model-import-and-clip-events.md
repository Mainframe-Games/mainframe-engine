# ADR 0208 — Skinned model import: skeletons, skins, clips and clip events

- **Date:** 2026-10-25
- **Status:** accepted
- **Milestone:** G1b (G1.10), issue #119
- **Docs:** docs/design/animation.md#import, docs/design/asset-pipeline.md

## Context

A Blender character exported as glTF (or FBX) must import into ADR 0207's `Skeleton3D`, a skinned `MeshInstance3D` and
an `AnimationPlayer` whose library holds the clips under the action names. The importer is Assimp (Silk.NET.Assimp,
native 6.0.2). glTF has no loop flag and no event markers, and Assimp does not read animation `extras`. Godot's
importer puts skinned meshes under the skeleton and loops clips named `…-loop`/`…-cycle`.

While testing, rotation keys came back scrambled: Silk.NET's `QuatKey` struct carries an `mInterpolation` field
(32 bytes) that the bundled native library's `aiQuatKey` does not have (24 bytes), so indexing `MRotationKeys[k]` read
the wrong keys.

## Decision

- **Skeleton:** bones are every node a mesh's bones name, the nodes between them and their common ancestor, and
  mesh-less subtrees below bones (end bones). The common ancestor's parent (or the ancestor itself when it is not a bone)
  becomes one `Skeleton3D` named after the armature; bone nodes leave the node tree. Non-bone children of bones become
  `BoneAttachment3D`s. A file whose root is a bone gets a new `Skeleton3D` at the model root.
- **Skinned meshes** move under the skeleton with an identity transform (glTF ignores a skinned mesh node's own
  transform), `Skeleton = ".."`, and a `Skin` of the union of their bones (`MOffsetMatrix` = inverse bind matrix).
  Weights: the four heaviest per vertex (Assimp's `LimitBoneWeights` is on), normalised. More than `Skin.MaxJoints` bones
  imports the mesh static with a warning. FBX pivots are not preserved (`IMPORT_FBX_PRESERVE_PIVOTS` = 0), so no
  `$AssimpFbx$` helpers become bones.
- **Clips:** one `Animation` per `aiAnimation`, named after the action without Blender's `Armature|` prefix; length =
  duration ÷ ticks per second; one track per changing channel (bones by `Bone`, other nodes by path from the model root,
  which owns the `AnimationPlayer`). Channels that never leave their rest are dropped, constant ones keep one key, and
  with `optimizeAnimations` (default) keys that linear interpolation reproduces are removed.
- **Loop modes and events, in increasing precedence:** a `-loop`/`_loop`/`-cycle`/`_cycle` name suffix (stripped);
  glTF `animations[i].extras` — `loop` (bool or mode name) and `events` (`{ "HammerFist": 0.42 }` or
  `[ { "name", "time" } ]`), which Blender writes from an action's custom properties with *Include → Custom
  Properties*; then the `.meta` `clips` list (`name`, `loop`, `rename`, `events`), which also covers FBX. The importer
  reads the extras from the `.gltf` JSON or the `.glb` JSON chunk itself (System.Text.Json, no new dependency).
- **Key stride:** the importer detects the native key stride from the data (the stride whose key times rise and stay
  inside the clip, trying Silk's size first) and reads keys through it. When Silk and the native library agree again
  this picks Silk's size and nothing changes.
- The import settings record gains `importAnimations`, `optimizeAnimations` and `clips` (value equality, so the import
  cache still hits).

## Consequences

- A Blender character imports with its actions playable by name, loops and events set without touching the engine;
  instances share the mesh, skin and library (`ModelImporter.Clone` copies exported values).
- The test character (`Tests/Assets/Models/Character/character.glb`, generated by `SkinnedCharacter`) is laid out as
  Blender exports one and covers both event forms and `.meta` clips.
- Morph targets, cameras and lights are still not imported; FBX clips get events only from the `.meta`.
