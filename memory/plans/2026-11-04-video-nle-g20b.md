# Plan: Video NLE G20b, the headless timeline library

**Status:** done (committed with G20b)
**Docs:** [Video NLE proposal](../../docs/design/future/video-nle.md) (§ Data model and code, § Export, scenarios G20b),
[ADR 0241](../decisions/0241-video-mode-nle.md), [Video editing mode](../../docs/design/video-editor.md)
**Started:** 2026-11-04

## Goal

`MainframeEngine.Video/Timelines/` holds a tested, UI-free multi-track timeline that G20c can put a UI on:
- the model;
- the `.mftimeline` file;
- every edit the proposal names for phase 1;
- layout maths, snapping and reframing;
- the export: a filter graph and ffmpeg arguments for each preset.

Today's video mode keeps working unchanged.

## Not in scope

- **Editor UI, preview and the media pool:** G20c.
- **Phase-2 fields:** titles, images, transitions, clip volume and fades. Each gets a field and a migrator step when its
  phase lands. Speed is in now: the model, layout and graph handle it, but no UI sets it before G20.2.
- **Deleting today's `.mfcut` code and `FilterGraphBuilder`:** that happens when G20c replaces the mode.

## Design notes (decided here)

- **Times** are seconds (`double`). Every edit snaps its inputs to the timeline's frame grid
  (`FrameRate.Snap`), and a clip's length is its kept source time ÷ speed, rounded to whole frames.
- **Export lengths are exact.** Each clip is padded by a frame and then trimmed to its exact length (`tpad`/`trim`,
  `apad`/`atrim`), so per-clip rounding never drifts across a track.
- **Reframing** uses `ClipLayout`:
  - It intersects the clip's destination rectangle with the frame.
  - The graph crops the source to the visible part, scales it, and pads it to a transparent full frame. `pad` takes
    no negative offsets, so a Fill clip larger than the frame still works.
  - Each track is one concatenated RGBA stream (clips and transparent gaps), so there is one `overlay` per track.
- **Inputs:** one `-ss In -t Len -i` per clip window, frame-accurate input seeking.
- **Audio:** each clip goes through `aresample`, stereo and `adelay`. Everything mixes into
  `amix=normalize=0:duration=longest`, padded and trimmed to the range. With no audio clips, `anullsrc` provides the
  track.
- **UIDs.** A timeline's UID is `vtl_` + 12 hex digits, read by the engine's AssetDatabase as a self-describing file
  (`.mftimeline` is added to `IsSelfDescribing` and `AssetUid.PrefixForExtension`). The library writes the same
  format; it does not reference the engine.
- **Locks.** An edit that would touch a locked track, its own clip or a linked partner, returns the same timeline
  reference. "Nothing changed" is reference equality, which is what G20c's undo will use.

## Steps

- [x] **Model.** `FrameRate`, `TimelineSettings`, `Track`/`TrackKind`, `MediaRef`, `ClipTransform`/`FrameFit`/
  `CropRect`, `Clip`, `Marker`, `Timeline` (immutable records), plus `TimelineFactory.New(settings)` with V1, V2, A1
  and A2. Verified by: model tests (frame snapping, default tracks).
- [x] **File format.**
  - `TimelineFile`, `TimelineSerializer` (`Serialize`, `Deserialize`, atomic `SaveAsync`/`LoadAsync`) and
    `TimelineMigrator` (version 1) on the `Projects/` pattern, with `TimelineFormatException`.
  - Validates each clip's partition and that every clip names a track of the right kind.
  - Engine: `.mftimeline` is self-describing, prefix `vtl`.
  - Verified by: `TimelineSerializerTests.RoundTripsAndRefusesNewer` (and bad input), plus an engine test that the
    AssetDatabase reads a timeline's embedded UID.
- [x] **Layout.** `TimelineLayout`:
  - clip length and end;
  - kept source ranges inside the window;
  - timeline ↔ source time;
  - clip at a time;
  - timeline duration.

  Verified by: `TimelineLayoutTests` (including `MapsAcrossCollapsedCut`, speed, frame rounding).
- [x] **Edits.** `TimelineEdits`:
  - AddTrack, RemoveTrack, SetTrack;
  - Insert, Overwrite, Append (linked V/A from a `MediaRef`);
  - Razor (some tracks, or all unlocked), Trim, RippleTrim, Lift, RippleDelete, Move (time and track);
  - Link, Unlink, SetTransform;
  - SetClipCuts (a `SegmentList` edit applied to the link group's clips of the same media, with ripple).

  Verified by: `TimelineEditsTests` (the proposal's G20b scenarios and edge cases).
- [x] **Snapping and reframe.** `Snapping` (candidates: clip edges, playhead, markers, in/out; nearest within a
  tolerance) and `ClipLayout` (Fit, Fill, Stretch, scale, position, crop, the visible part). Verified by: `SnappingTests`,
  `ClipLayoutTests.FillAndFitIntoVertical` and more.
- [x] **Export.**
  - `ExportPresets`: the proposal's table, with sizes resolved against the timeline's aspect and the size-capped
    bitrate.
  - `TimelineGraphBuilder`: inputs and graph for a range.
  - `TimelineExportArguments`: the full ffmpeg arguments for a preset and an encoder.
  - `TimelineExporter`: runs ffmpeg with progress, cancel, deleting partial output, and refusing a source as the output.

  Verified by: `TimelineGraphBuilderTests` (1 clip; 2 tracks with a gap; speed; reframe; muted and solo tracks; range;
  GIF), `ExportPresetsTests.SizeCapBitrate`, argument tests.
- [x] **Filmstrip and the opt-in ffmpeg test.**
  - `FilmstripExtractor` gives the arguments for an `fps=1/N,scale=-2:h,tile` filmstrip PNG, plus a runner.
  - `just test-video-ffmpeg` runs `TimelineFfmpegTests` (skipped unless `MAINFRAME_VIDEO_FFMPEG_TESTS=1`): real
    ffmpeg renders lavfi sources through each preset's graph, and ffprobe checks the size, rate and duration.

  Verified by: argument tests, and the recipe run on this machine.
- [x] **Docs and gates.**
  - `video-editor.md` gets a short "Timeline library (G20b)" section pointing at the proposal;
  - the proposal's code table, plus anything this plan changed;
  - `AGENTS.md` (the video entry).

  Gates: `just build`, the Release build, `just test`, `just format-check`, `check.sh`, `just test-video-ffmpeg`, then
  a local commit.

## Done when

- `Tests/MainframeEngine.Video.Tests/Timelines/` holds a test for every G20b scenario in the proposal, and all of them
  pass.
- `just test-video-ffmpeg` exports a two-track 1080×1920 timeline (a reframed 16:9 clip and a gap) through the TikTok,
  GIF and X presets, and ffprobe reports the expected size, rate and duration.
- No file outside `MainframeEngine.Video/`, its tests, the engine's AssetDatabase/AssetUid (plus a test), the
  justfile and docs changes.
