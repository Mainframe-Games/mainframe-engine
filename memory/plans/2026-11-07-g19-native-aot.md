**Started:** 2026-11-07

## Goal

An export preset with `"nativeAot": true` publishes the game as one native executable (plus the engine's native
libraries and `Assets.mfpak`): no managed game or engine assembly ships, so neither the code nor the pack key can be
read back with ILSpy. The engine assembly is trim- and AOT-clean, with the analyzers as errors. Crash reports from a
NativeAOT build symbolicate from the `symbols: separate` zip.

## Spike (2026-11-07, before the plan)

The template game published with `PublishAot=true` on osx-arm64 compiled with 24 ILC warnings and ran headless, but a
windowed run never quit: `Node.FindOverrides` reflects over each node type for `OnProcess`/`OnInput` overrides, and
NativeAOT keeps no metadata for them, so no node processed (the loading screen never faded, `--max-frames` never
counted). The Steamworks shim is not compiled in (`SteamApi.*` "will always throw"). `-p:PublishAot=true` as a global
property fails on the netstandard2.0 generator project (NETSDK1207). The engine has 22 trim/AOT analyzer sites.

## Not in scope

- Windows NativeAOT run (no Windows host here; the plan, validator and staging paths are unit-tested, the publish is
  the SDK's). CI jobs (owner decides: one NativeAOT export per OS would spend minutes).
- The editor and tools stay JIT; mobile (M12.6) and consoles (C0) reuse this.
- Brotli versus zstd (owner, unchanged).

## Steps

- [x] Engine AOT-clean: `IsAotCompatible` on the engine and the Steamworks shims; the trim/AOT diagnostics errors in all
  of `Src` (`.editorconfig`); fix `Node` (type-level `[DynamicallyAccessedMembers]`), `Tween`, `SdlEventBatch`,
  `ConfigFile`, `TypeRegistry`, `GameAssemblyLoader`, `SteamworksLoader`, `CrashBundleWriter`. Verified by: the Release
  build with 0 warnings; ILC on the template game reports nothing from engine code.
- [x] Build plumbing (ADR 0259): `-p:MainframeNativeAot=true` → `PublishAot` in game projects (`MainframeGame.props`);
  the Steamworks shim and Facepunch assembly of the target OS compiled in; no `steamworks/` folder, managed PDBs or XML
  docs in the publish; the macOS bundle apphost step skipped; a NativeAOT executable in `X.app/Contents/MacOS` runs with
  `../MonoBundle` as its base directory. Verified by: the template game exported with `nativeAot: true` runs windowed
  and headless and exits 0; with Steam on it reaches `SteamClient.Init`.
- [x] Preset key and validator: `nativeAot` in `DesktopExportOptions`, the format reader/writer, `ExportPlan` arguments,
  `native-aot-host` (error) and `native-aot-ignored` (warning), the editor's Export dialog row, `mf-export --native-aot`.
  Verified by: `NativeAotNeedsAHostOfTheTargetOs`, `NativeAotIgnoresReadyToRunAndSingleFile`, plan/format tests.
- [x] Staging and symbols: a NativeAOT stage fails on any managed assembly; `symbols: separate` moves the native symbol
  file (`.dSYM`, `.dbg`, `.pdb`) into the zip. Verified by: runner tests with a fake publish,
  `NativeAotExportHasNoManagedAssemblies` (real SDK, this machine's RID).
- [x] Native crash frames (ADR 0260): `CrashFrame.NativeOffset`/`NativeImage` from `StackFrame.GetNativeIP` in a
  NativeAOT process; `mf-symbolicate` resolves them with `atos`/`addr2line`/`llvm-symbolizer` from the symbols folder.
  Verified by: unit tests for the frame, tool selection and output parsing; locally, a forced crash in an AOT export
  symbolicated to its source line.
- [ ] Prove: macOS (template smoke with `NATIVE_AOT=1`), Linux in Docker (`build/linux/run.sh aot`, clang + zlib in the
  image). Verified by: both runs' logs in the log file.
- [ ] Ship (move): the proposal becomes `docs/design/protected-exports.md` with "Changes from the proposal, phase 4";
  links repointed; `game-export.md`, `asset-pipeline.md#packs`, `crash-reporting.md`, README, landing page; G19 ✅.
  Verified by: `check.sh`, the gates.

## Done when

  runs headless with exit 0 on macOS and in the Linux container.
- The gates in `.agents/workflow.md` pass and the G19 row is ✅.
