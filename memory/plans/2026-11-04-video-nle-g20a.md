# Plan: Video NLE G20a, engine prerequisites

**Status:** in progress
**Docs:** [Video NLE proposal](../../docs/design/future/video-nle.md) (§ Engine work, scenarios G20a),
[ADR 0241](../decisions/0241-video-mode-nle.md), [Gameplay recording](../../docs/design/recording.md),
[Game export](../../docs/design/game-export.md), [Distribution](../../docs/design/distribution-nuget.md)
**Started:** 2026-11-04

## Goal

The engine pieces the video NLE needs, each useful on its own:
- OS file drops reach the scene tree.
- `Assets/Video` never reaches a game's build output or an export.
- The editor's recordings land in the project.
- A code-created `Texture2D` whose pixels change updates its GPU image in place.

## Not in scope

- Any video-mode UI. The editor only logs a drop here; G20c routes drops to the media pool and the timeline.
- Moving or migrating recordings already in user data.
- G19's pack writer, which does not exist yet: only the shared predicate and a note in its proposal.

## Steps

- [x] **Drop event.**
  - `SceneTree.FilesDropped` (`event Action<FilesDroppedEvent>`, holding `Paths` and `Position`) and `NotifyFilesDropped`
    in `Scene/SceneTree.Window.cs`.
  - `Engine` subscribes `Window.FileDrop` next to `Window.Closing`.
  - The position comes from SDL's global mouse minus the window position (`SilkWindowControl.PointerInWindow`), in the
    same window points as mouse events.
  - The editor logs drops in `EditorApp`.
  - Verified by: `FilesDroppedTests` (raised once with the paths and position; no subscriber is fine). By hand: drop a
    file on `just editor` and read the log line.
- [x] **Editor-only folder.**
  - `ContentPaths.EditorOnlyFolder = "Assets/Video"` and `ContentPaths.IsEditorOnly(projectPath)` (either separator,
    case-insensitive).
  - The MSBuild target `_MainframeExcludeEditorOnlyContent` in `build/MainframeGame.props` removes `None`/`Content`
    items under `<project>/Assets/Video/` before `AssignTargetPaths`. The package imports this file through
    `buildTransitive/MainframeEngine.props`, so checkout and package games both get it.
  - `ContentFilter.Ships` is false for editor-only paths.
  - `ExportValidator` warns (`editor-only-content`) when an include glob names `Assets/Video` explicitly. Correction to
    the proposal: the default `Assets/**` gives no warning, or every project with videos would warn on every export.
  - A line in `docs/design/future/protected-exports.md` makes the pack writer use the same predicate.
  - Verified by:
    - `ContentPathsTests.IsEditorOnly`, `ContentFilterTests.EditorOnlyFolderNeverShips`, and an `ExportValidatorTests`
      warning case;
    - `just template-smoke`, which now puts `Assets/Video/Media/clip.mp4` in the game and requires `bin/` (and, for
      package games, the publish folder and archives) to have no `Assets/Video`.
- [x] **Recordings into the project.** `RecordingPaths.Directory(projectRoot)` returns `Assets/Video/Recordings`.
  `PlayController` passes the project root, not user data; Play always has a project, so there is no fallback.
  Correction to the proposal: the "no project → user data" case does not exist in the editor, and the game run from a
  terminal takes an explicit `--record` path. Verified by: `RecordingPathsTests` updated (the path is under
  `Assets/Video/Recordings`).
- [x] **In-place texture updates.**
  - `GpuTexture.Update2D(rgba)` re-uploads mip 0 of a one-mip 2D RGBA8 texture through `UploadQueue.UploadImage`, whose
    barrier already orders it after earlier frames' reads.
  - `VulkanCanvasRenderer.Prepare` uses it when the entry's size matches, the texture has no mips, and the version
    changed. Descriptor sets stay as they are.
  - Verified by the render test `CanvasTextureUpdatesInPlace`, a new host scene `canvas-texture-update`. Each frame a
    64×64 sprite texture is set to red, green or blue by frame number:
    - capture pixels match each frame's colour exactly;
    - the validation gate is clean;
    - allocation gate: 0 B over 240 frames. A re-created `GpuTexture` allocates, so this proves the in-place path.
- [x] **Docs.**
  - `recording.md` (where recordings go);
  - `editor.md` (drop log; a pointer to G20c);
  - `game-export.md` and `distribution-nuget.md` (editor-only folder);
  - `video-editor.md` (where recordings live now);
  - the proposal's G20a rows and scenarios: the corrections above;
  - AGENTS.md if the structure text changes.

  Verified by: `just docs-build`.
- [ ] **Gates.**
  - `just build`; Release build with `-warnaserror`;
  - `just test`, `just test-render`, `just format-check`, `just shaders-check`;
  - `bash .agents/mainframe-workflow/scripts/check.sh`;
  - `just template-smoke`.

## Done when

- All gates above pass, with the template smoke on this machine.
- A game built from the template with a file in `Assets/Video/Media` has no `Assets/Video` folder in `bin/`.
- Dropping a file on the running editor logs its path and a position inside the window.
- Pressing Play and Record in the editor writes the MP4 under the project's `Assets/Video/Recordings`.
- `CanvasTextureUpdatesInPlace` passes with 0 B allocated.
